# 인용 규칙과 검증 상태

검증기(`scripts/citations.py`, CLI `legal.py verify`)가 읽을 수 있는 형식으로 쓰면 자동 검증되고, 못 읽는 형식은 `UNRESOLVED`(실패)가 된다.

## 1. 법령

| 쓰기 | 예 | 검증기가 확인하는 것 |
|---|---|---|
| 정식 법령명 + 조 | `「개인정보 보호법」 제15조` | 법령 실재(정확 일치), 조 실재, 삭제 여부, 기준일 시행 여부 |
| 가지조문 | `근로기준법 제76조의2` | `제76조`가 아니라 `제76조의2` 자체 |
| 항·호·목 | `제15조제1항제1호`, `제2조제1호가목` | 해당 항·호·목 실재 |
| 제목 병기 | `민법 제750조(불법행위의 내용)` | 원문 제목과 일치(“불법행위의 책임”이면 불일치) |
| 나열 | `제15조 및 제17조`, `제15조제1항제1호 및 제2호` | 나열된 각각 |
| 같은 법 | `같은 법 제17조`, `같은 법 시행령 제14조의2` | 직전에 인용한 법령으로 해석 |
| 약칭 정의 | `「개인정보 보호법」(이하 "법"이라 한다) … 법 제17조` | 정의한 약칭만 허용 |
| 인용문 | `제76조의2는 “사용자 또는 근로자는 …”라고 규정` | 따옴표 안 문구가 원문에 그대로 있는지(공백·가운뎃점 차이는 무시, `…` 생략 허용) |
| 구법 | `구 개인정보 보호법 제8조` | 삭제·폐지 조문도 구법 인용으로 허용 |
| 시행예정 | `2027. 6. 10. 시행 예정인 개정 근로기준법 제60조제9항` | 문맥에 '시행 예정/개정 법률'이 있으면 미시행 조항 허용(경고) |

쓰지 말 것: `중처법`·`근퇴법` 같은 약칭(정의 없이), 법령명 없는 `제15조`, `민법상 750조`처럼 '제' 없는 비공식 표기(추출은 되나 권장하지 않음),
앞에 수식어를 붙인 법령명(`특별 근로기준법` → 그런 법령은 없으므로 `UNRESOLVED`).

## 2. 판례·결정·해석

| 쓰기 | 예 | 확인 |
|---|---|---|
| 대법원 | `대법원 2021. 9. 16. 선고 2021다219529 판결` | 사건번호 실재, 선고일, 법원 |
| 전원합의체 | `대법원 2024. 12. 19. 선고 2020다247190 전원합의체 판결` | 위 + 판결문에 '전원합의체' 표기(경고 수준) |
| 병합 | `… 선고 2020다247190, 2023다302838 전원합의체 판결` | 각 사건번호(선고일은 앞 인용에서 승계) |
| 하급심 | `서울고등법원 2009. 8. 18. 선고 2008나40467 판결` | **법원명 필수** — 하급심 사건번호는 법원마다 겹친다(예: `2008브4` 는 대구지법·울산지법에 각각 존재) |
| 헌재 | `헌법재판소 2016. 10. 27. 선고 2013헌마576 결정` | DRF `detc` 필요(미러에 헌재 결정 없음) |
| 판시 인용 | `… 판결은 “종전 판례가 제시한 고정성 개념은 …”이라고 판시` | 판시사항·판결요지·판례내용에 그대로 있는지 |
| 법제처 해석 | `법제처 22-0733 해석` / `안건번호 22-0733` | DRF `expc` 필요 |

## 3. 검증 상태와 고치는 법

| 상태 | 뜻 | 고치는 법 |
|---|---|---|
| ✅ `VERIFIED` | 출처에서 확인, 인용 속성 일치 | 경고(⚠)가 있으면 읽고 필요 시 문구 보완 |
| ❌ `MISMATCH` | 존재하나 속성 불일치: 제목·선고일·법원·인용문·삭제·폐지·**기준일 미시행** | 원문을 다시 열어 속성을 고치거나 다른 근거로 교체 |
| ❌ `NOT_FOUND` | 사용 가능한 공식 출처 어디에도 없음(가지조문·항·호·사건번호 가공 의심) | 인용 삭제. 미공개 판결이면 원문을 확보하기 전에는 인용하지 않는다 |
| ❌ `UNRESOLVED` | 무엇을 가리키는지 특정 불가(약칭·법령명 없음·선행어 없는 '같은 법'·수식어 붙은 법령명) | 「정식 법령명」으로 다시 쓴다 |
| ⚠ `UNVERIFIABLE` | 출처 부재로 확인 자체를 못 함(네트워크 차단, 미러 없음, 헌재·해석례인데 DRF 불가) | 출처를 갖추거나 사용자에게 한계를 알리고 `--accept-incomplete` 로 명시 |

문서 판정: `PASS`(인용 ≥1, 전부 VERIFIED) · `FAIL` · `INCOMPLETE` · `NO_CITATIONS`(검증할 인용 없음 — 통과가 아니다).

## 4. 시행일(as-of) 판정

- 미러의 판본 시행일자가 기준일 이후면 **시행예정 판본**이다. 이때 인용 단위(조·항·호)에
  - `<신설 공포일>` → 아직 없는 조항: `MISMATCH`(문맥에 시행예정 명시 시 경고로 완화)
  - `<개정 공포일>` → 조항은 있으나 문언이 바뀜: 경고(따옴표 인용은 현행 문언으로 재확인)
  - `삭제 <공포일>` → 아직 시행 중(삭제 예정): 경고
  - 표시 없음 → 그 개정의 대상이 아님(추정): 경고
- legalize-kr **전체 이력**(`setup --full-history`)이 있으면 기준일에 시행 중인 커밋을 직접 찾아 **정밀 판정**한다(추정 아님).
- 최근 400일 안의 다른 개정 표시가 있으면 부칙상 조항별 시행일을 DRF `조문시행일자`로 확인하라는 경고가 붙는다.
- 부칙의 조항별 시행일·경과규정·행위시법 문제는 검증기가 판단하지 않는다 — 조사관·감사관이 부칙을 직접 읽는다.

## 5. 검증기가 보증하지 않는 것

조문·판례의 **실재와 인용 속성**을 보증할 뿐, 그 조문을 이 사안에 적용한 **법리 판단이 옳은지**는 보증하지 않는다.
그것은 반대논리 감사관·독립 감사관·최종적으로 변호사의 몫이다.
